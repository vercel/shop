The storefront includes Shop Agent, a shopping assistant built with [Eve](https://eve.dev). It helps shoppers discover products, browse collections, ask store-policy questions, and manage the same cart used throughout the storefront.

Shop Agent is disabled by default. Set `agent.isEnabled` to `true` in `lib/config/index.ts` to enable it. It uses the existing Shopify credentials and requires AI Gateway access to generate responses. Customer login is optional.

## Run the assistant

After enabling Shop Agent, run `pnpm dev` locally. Eve starts alongside Next.js and shares the browser's origin, including localhost. On Vercel, the Next.js integration builds and mounts Eve as a service in the same project.

For local production, run `pnpm build:agent && pnpm build`, then run `pnpm exec eve start --port 4274` and `pnpm start` in separate terminals. The built Next.js routes forward Eve requests to port 4274.

The included model is OpenAI GPT-5.6 Luna through Vercel AI Gateway. Use Vercel's deployment identity or configure `AI_GATEWAY_API_KEY` when needed. See [Environment Variables](/docs/reference/env-vars).

Open the assistant and send a product question. A response should show current Shopify products; selecting a product can show variant choices without leaving the conversation.

A saved conversation starts restoring in the background when the storefront loads. The assistant stays closed until the shopper opens it.

## Shopify connections

Eve discovers catalog tools from Shopify's UCP endpoint and policy answers from Storefront MCP. Product cards, recommendations, collections, and cart changes call Shopify directly through shared data operations and Hydrogen handlers.

The agent publishes its public profile at `/agent/ucp-profile.json`, using the configured site origin. The merchant profile remains at `/.well-known/ucp`. Local development and Vercel previews use Shopify's public example profile because localhost and protected previews may be unreachable from Shopify. Set `UCP_AGENT_PROFILE_URL` only to override this behavior.

Color or size options you request filter the products shown. Without a requested color or size, results are not restricted to one. If semantic search is unavailable, the assistant can use keyword search. Policy questions use Shopify's answers rather than the model's memory.

## Cart and checkout

The assistant uses the cart identified by the storefront's cookie, not a cart ID chosen by the model. Before sending a message, the storefront ensures a cart exists. When customer authentication is enabled, cart creation preserves the customer association when the session is usable or refreshable.

Shoppers can add a chosen variant, change quantities, remove lines, and add a cart note. A confirmed change shows a short confirmation in the conversation and opens the cart drawer once its contents have refreshed. The assistant does not show another variant picker or cart summary in that reply. In replies without a cart change, those controls appear only after the assistant finishes replying. Restoring a conversation does not repeat cart changes or reopen the drawer.

Stop requests cancellation of the Eve turn. Clear requests cancellation and starts a fresh conversation, including while saved messages are loading. If cancellation cannot be confirmed, the assistant warns the shopper to inspect the cart before requesting another change. A Shopify write that has already started may still finish.

Checkout in that browser tab waits while the assistant is busy or cart reconciliation is pending. Wait for the response before checking out in another tab.

Eve records completed tool steps, but a step interrupted during execution can run again. Cart writes do not have application-level deduplication. Inspect the cart after an interrupted response and before requesting another change.

Checkout remains a shopper action through the storefront's checkout button. The assistant cannot complete payments or cancel orders.

## Privacy and access

Conversations are stored by Eve on the server. The browser stores a conversation reference and draft, not a copy of the full transcript. Sessions have a one-day lifetime. Clearing chat discards the browser's reference; it does not delete server records or information already sent to the model provider. Session expiry is not a data-deletion policy.

The default browser channel permits anonymous access. A session ID is not a user-ownership check: anyone who obtains one may be able to read or control that conversation. Do not share session IDs or use this default channel for private customer-account or support data. Add application authentication and session-ownership checks before introducing private conversations.

Cart tools expose an item summary and mutation warnings, not the full cart or gift-card recipient details. Personal information shoppers type into chat still reaches Eve and the model provider. Configure retention and operational access for those services before serving production traffic.

## Production limits

Each conversation has a usage limit. When it is reached, the assistant stops accepting new messages and prompts the shopper to clear the chat to start a new conversation.

BotID is configured separately and disabled by default. Enable `botid.isEnabled` on Vercel to protect anonymous browser requests. Bot detection is not user authentication or a spending cap. Add deployment-level rate limits and Gateway spending controls appropriate to public traffic.

The assistant has no shell, file, general web-browsing, or delegation tools. Its Shopify connections expose only catalog and policy reads; cart writes use Hydrogen's server handlers.

## What’s next

Adjust the model, instructions, or product presentation for your store. Preserve Shopify as the source of product facts and keep cart identity outside model input. Private or cross-device history requires customer-linked authorization and a retention/deletion policy. Add durable operation receipts or upstream idempotency before requiring replay-safe cart writes.
