The storefront includes a shopping assistant built with [Eve](https://eve.dev). It helps shoppers discover products, browse collections, ask store-policy questions, and manage the same cart used throughout the storefront.

The assistant is enabled by default. It requires AI Gateway access, a private Redis database, and a stable session secret. Customer login is optional. Set `agent.isEnabled` to `false` in `lib/config/index.ts` to disable it.

## Enable the assistant

1. Create an Upstash Redis database and configure `AGENT_REDIS_URL` and `AGENT_REDIS_TOKEN` with its REST credentials. Use separate credentials or deployment origins for separate environments.
2. Generate a secret with `openssl rand -base64 32` and set `AGENT_SESSION_SECRET`. Keep the same value across instances. Rotating it invalidates browser access to existing conversations.
3. Set `AGENT_STOREFRONT_URL` to the exact browser-facing origin, including the local port during development. Production and preview deployments each need their own HTTPS origin. Eve uses this URL to reach the storefront's protected commerce adapter.
4. Set `agent.isEnabled` to `true` in `lib/config/index.ts`. The included model is OpenAI GPT-5.6 Luna through Vercel AI Gateway.
5. Run `pnpm dev` locally. On Vercel, the Next.js integration builds and mounts Eve as a service in the same project. For local production or self-hosting, run `pnpm build:agent` before `pnpm build && pnpm start`.

When deployment protection blocks Eve's commerce requests, provide `VERCEL_AUTOMATION_BYPASS_SECRET`. Keep this credential server-only. See [Environment Variables](/docs/reference/env-vars) for the complete setup reference.

Open the assistant and send a product question. A response should show current Shopify products; selecting a product can show variant choices without leaving the conversation.

## Shopify connections

Eve discovers catalog tools from Shopify's UCP endpoint and policy answers from Storefront MCP. Product cards, recommendations, collections, and cart changes use the storefront's validated data operations and Hydrogen handlers.

The agent publishes its public profile at `/agent/ucp-profile.json`. The merchant profile remains at `/.well-known/ucp`. Set `UCP_AGENT_PROFILE_URL` to override the agent profile URL, for example when testing a protected preview through a public endpoint. Local Eve development uses Shopify's public example profile because Shopify cannot fetch localhost.

Required color or size options filter the products shown. If semantic search is unavailable, the assistant can use keyword search. Policy questions use Shopify's answers rather than the model's memory.

## Cart and checkout

The assistant uses the shopper's existing cart. A first conversation can create an empty cart; when customer authentication is enabled, creation preserves the customer association when the session is usable or refreshable.

Shoppers can add a chosen variant, change quantities, remove lines, and add a cart note. The storefront refreshes the cart after a response settles. Restoring a conversation never resubmits an old cart change.

Stop requests cancellation of the Eve turn. A Shopify write that has already started may still finish. Clear waits for an active response to settle before starting a fresh conversation. Checkout is unavailable while the assistant is busy or cart reconciliation is pending. An interrupted cart write can temporarily block further assistant writes and checkout for up to two minutes; inspect the cart before requesting another change.

Checkout remains a shopper action through the storefront's checkout button. The assistant cannot complete payments or cancel orders.

## Privacy and access

Conversations are stored by Eve on the server. The browser stores a conversation reference and draft, not a copy of the full transcript. Sessions have a one-day lifetime. Clearing chat discards the browser's reference; it does not delete server records or information already sent to the model provider. Session expiry is not a data-deletion policy.

A signed HttpOnly cookie and private session records restrict each conversation's messages, stream, and controls to its browser session. Cart identity is supplied by the application, not chosen by the model. If the active cart is replaced, clear the conversation before continuing. Redis stores session ownership and cart bindings for one day and mutation receipts for two days.

Cart tools expose an item summary and mutation warnings, not the full cart or gift-card recipient details. Personal information shoppers type into chat still reaches Eve and the model provider. Configure retention and operational access for those services before serving production traffic.

## Production limits

BotID is configured separately and disabled by default. Enable `botid.isEnabled` on Vercel to protect assistant requests. A per-browser-session limit allows 20 message requests per minute, but it is not an IP rate limit or a spending cap. Add deployment-level rate limits and Gateway spending controls appropriate to public traffic.

The assistant has no shell, file, general web-browsing, or delegation tools. Its Shopify connections expose only catalog and policy reads; cart writes pass through the application-owned replay protection.

## What’s next

Adjust the model, instructions, or product presentation for your store. Preserve Shopify as the source of product facts and keep cart ownership outside model input. Cross-device history requires customer-linked authorization and a retention/deletion policy; do not expose a conversation merely because someone knows its ID.
